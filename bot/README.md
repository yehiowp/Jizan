# GMGN 迷因幣 Telegram 機器人

用 GMGN 官方 `gmgn-cli` 執行交易的 Telegram 機器人：掃描候選幣、跑完整安全檢查、你在 Telegram 按確認後才下單，並且在買入的同時把停損停利掛到 GMGN 伺服器端。

兩種模式：

- **手動**（預設）：機器人找到候選就通知你，你按確認鍵才下單。
- **自動**：武裝之後它自己選、自己買，不再問你。門檻比手動嚴，武裝會自己到期。

## 先講清楚

- **不保證獲利。** 迷因幣絕大多數歸零。這支程式能做的是過濾掉明顯的陷阱、強制固定部位大小、確保每一單都有停損。它不預測價格。
- **自動模式會更快賠光。** 它照單全收每個符合條件的訊號，沒有「這個我看不順眼」這種判斷。所以自動模式的門檻設得比手動高，而且有每日筆數與金額上限。
- **不碰你的私鑰。** 私鑰由 `gmgn-cli` 自己管在 `~/.config/gmgn/.env`，這支程式不讀、不存、不傳。
- **摩擦成本是真的。** 每次進出都要付 GMGN 抽成 + 優先費 + 小費 + 滑價。用 $20 的部位去對抗這個摩擦，勝率門檻比你想的高很多。

## 需要準備

| 項目 | 怎麼拿 |
|---|---|
| Node.js 20+ | |
| `gmgn-cli` | `npm install -g gmgn-cli` |
| GMGN API Key | `gmgn-cli config` 給你申請連結（連結已帶好公鑰），建立後 `gmgn-cli config --apply <KEY>` |
| 交易錢包 | 在申請頁的「交易錢包」欄位選一個 GMGN 帳戶錢包。**錢要匯到那一個。** |
| 2FA | 申請頁的「允許交易」權限需要先綁定 2FA |
| Telegram Bot Token | 跟 [@BotFather](https://t.me/BotFather) 說 `/newbot` |
| 你的 Telegram ID | 跟 [@userinfobot](https://t.me/userinfobot) 說句話 |

⚠️ `gmgn-cli` **只走 IPv4**。主機開著 IPv6 會拿到 401/403，而且錯誤訊息看不出真正原因。

⚠️ **`gmgn-cli config` 產生的 Ed25519 金鑰是用來簽 API 請求的，不是交易錢包。** 公鑰上傳到 GMGN，私鑰留在 `~/.config/gmgn/.env`。交易錢包是你在申請頁選的那個 GMGN 帳戶錢包，錢匯到那裡。

⚠️ **`gmgn-cli config` 每跑一次就產生一組新金鑰。** 拿到連結後不要再跑一次 `config`，否則你申請到的 API Key 會對應到已經被覆蓋掉的舊金鑰。

⚠️ **「交易受信任 IP」留空。** 填了之後家用 IP 一變動（重開機、換網路）API 就會失效，而且錯誤訊息看不出原因。

## 安裝

```bash
cd bot
npm install
npm run setup
```

`npm run setup` 是問答式的設定精靈，只問三題（Telegram Token、你的 Telegram ID、錢包位址），填錯會當場擋下來，`.env` 裡其他設定和註解原樣保留。手機上請用這個 —— 用 nano 編設定檔，開錯目錄時它只會開一個空白檔案，不會告訴你開錯了。

要手動編也行：`cp .env.example .env`，然後填 `TELEGRAM_TOKEN`、`OWNER_ID`、`GMGN_WALLET_ADDRESS`。

## 卡住了就先跑這個

```bash
node doctor.mjs
```

零依賴，**不用先 `npm install` 就能跑**。它會逐項檢查 Node 版本、相依套件、`gmgn-cli`、API Key、網路、IPv6、`.env` 每一欄、Telegram token 是否有效、錢包地址與餘額，每個問題都直接給你要打的指令。Windows 會給 PowerShell 的寫法。

## 接本機 Meme 雷達（可選，但強烈建議）

[meme-radar](https://github.com/nhovongoc0-max/meme-radar) 是一個本機的唯讀掃描器。設定之後，候選名單改由它提供，機器人**完全不再敲 GMGN 的熱門榜**：

```bash
RADAR_URL=http://127.0.0.1:3791
```

改完 `/restart` 生效，`/status` 會顯示目前的候選來源。

**為什麼值得接**：發現階段是請求量的大宗——每輪掃描、每條鏈都要 `trending` + `hot-searches`。雷達已經在做這件事（而且每 20 秒刷新一次），兩個程式各自去敲 GMGN 只是在互相搶同一份額度。這是被限流最常見的原因。

### 一條界線：雷達只能縮小名單，不能核可任何一顆幣

雷達回傳的欄位**不含 GMGN 的安全欄位**（貔貅、`rug_ratio`、開發者持倉…），而閘門對未知欄位是不扣分的。如果直接拿雷達的資料當閘門輸入，每顆幣都會以「沒有紅旗」的姿態通過。

所以拿到地址之後，機器人仍然自己跑 `vet()`（`token info` + `token security`），由 **GMGN 的原始欄位**決定買不買。雷達影響的只有「先驗誰」。`/scan` 的輸出會把雷達來的幣標成**未驗證**。

其他幾個刻意的選擇：

- **雷達連不上時不會自動改敲 GMGN**（`RADAR_FALLBACK_TO_GMGN=false`）。自動退回去等於把「兩邊搶額度」的問題默默放回來，而你不會知道。那一輪那條鏈就沒有候選，紀錄裡會寫原因。
- **「雷達沒開」跟「雷達說沒有候選」分得出來。** 混為一談的話，雷達掛掉會看起來像「今天沒有機會」——那是最不該被誤判成平靜的狀況。
- **雷達的輸出一律當成不可信資料**：鏈對不上就丟掉、地址格式不合就丟掉、讀不到的欄位留空而不是補 0、幣名過濾控制字元與雙向文字覆寫。

⚠️ 雷達用的是**唯讀** API Key（它的說明也明講不要開交易權限）。機器人用的是另一把。兩把 Key 都在你自己的電腦上。

## 回測

```bash
npm run backtest                                   # 預設 14 天、25 顆、15m K 線
npm run backtest -- --days 30 --tokens 40 --resolution 1h
```

拿真實 K 線算「照這套停損停利規則進出場會怎樣」，三種滑價情境各跑一遍（0% / 單邊 3% / 單邊 8%），並附上「買進抱著不動」的對照組。停機線有模擬進去——不然報表會出現淨值變負數的回撤，而那是永遠不會發生的數字。

**它測的是出場規則，不是選幣。** 閘門讀的流動性、籌碼集中度、貔貅旗標、聰明錢人數，GMGN 只給現在的值，沒有歷史快照，所以沒辦法重建「三天前那顆幣在閘門眼裡長什麼樣」；熱門榜也只有現在的。

**而且候選名單有嚴重的存活者偏差**：名單來自現在的熱門榜，已經歸零的幣不在上面，但機器人真的跑起來會遇到它們。所以每個數字都是**上限**，不是預期值。

同一根 K 線同時碰到停損和停利時一律算停損——哪個先發生無從得知，而假設成停利會讓迷因幣的回測憑空好一大截。報表會印出這種「同根觸發」的比例，超過 20% 就代表結果禁不起挑戰。

要回答「這套選幣在現在的市場有沒有用」，唯一的辦法還是 `DRY_RUN=true` 跑一週看 `/stats`。

## 上線順序（不要跳步）

### 第一步：自檢（不花錢）

```bash
npm run selftest
```

會逐項檢查 API Key、IPv6、gas 報價、trending 資料源、安全檢查端點、報價、Telegram 連線。**有任何 ❌ 就先修，不要往下走。**

### 第一點五步：驗欄位（**這步不要跳**）

```bash
npm run verify -- <隨便一顆幣的合約地址>
```

**2026-09 已用真實 API 驗過**：`gas-price` 全部欄位對上（含 `average_prio_fee=1` 佔位值陷阱實測確認），`market trending` 27 個欄位全部對上。但 API 隨時會改，換機器、隔一段時間就再跑一次。

這支程式所有欄位名稱都是照 GMGN 官方 skills 的文件寫的。第三方 API 隨時會改欄位，而欄位改名的失敗方式通常不是報錯 —— 是**算出一個看起來正常的錯誤數字**。例如 `native_token_usd_price` 改名，換算出的下單數量會變成 0 或 NaN；`price_change_percent5m` 改名，5 分鐘暴跌的紅旗就直接失效，你會在下落的刀口上進場。

`verify` 會逐欄告訴你「缺了會怎樣」，關鍵欄位對不上就 exit 1。也可以單獨驗：

```bash
gmgn-cli gas-price --chain sol --raw | node src/verify-fields.js gas
gmgn-cli market trending --chain sol --interval 5m --limit 3 --raw | node src/verify-fields.js trending
```

### 第二步：模擬跑一週（`DRY_RUN=true`）

```bash
npm start
```

在 Telegram 用 `/scan` 找候選、`/buy <地址>` 走完整流程。它會照真實報價記帳，但不送鏈上交易。

**想直接看自動模式**：`.env` 設 `AUTO_BUY=true`，重啟，`/auto on`。模擬模式下它會自己選、自己記帳，但不會花錢。這是觀察它選幣品質最省錢的方式 —— 跑幾天看 `/stats`。

一週後看 `/stats`：

- **期望值是負的** → 這套打法在現在的行情下不賺錢。改參數或收手，不要拿真錢去試。
- **期望值是正的但只有 5 筆** → 樣本太少，那是運氣。繼續跑。

### 第三步：真錢（確定要再做）

```bash
# 在 .env 把 DRY_RUN 改成 false，然後：
export GMGN_ALLOW_AUTOMATED_TRADES=1
npm start
```

`GMGN_ALLOW_AUTOMATED_TRADES=1` **必須由你自己在 shell 設定**。這是 GMGN 的程式碼層防線：CLI 平常會從 `/dev/tty` 讀一個手打的 `yes`，`--yes` 這個旗標單獨用會被拒絕，就是為了擋掉「AI 讀到惡意指令就自己加 `--yes`」。官方文件把這個環境變數留給「刻意的無人值守自動化」，而設定它的人必須是操作者本人。

這支程式不會、也不該替你設定它。沒設定的話，真錢模式會直接拒絕啟動並告訴你原因。

要跑真錢自動交易，三道開關要同時成立，缺一不可：

1. `.env` 裡 `DRY_RUN=false`
2. 你的 shell 裡 `GMGN_ALLOW_AUTOMATED_TRADES=1`
3. `.env` 裡 `AUTO_BUY=true`，**而且**在 Telegram `/auto on` 按下確認

第 3 項有時效，另外兩項沒有。

## 指令

| 指令 | 作用 |
|---|---|
| `/hot [1h]` | 現在最熱的題材（IP），含領頭幣與仿盤警告 |
| `/auto on` | 武裝自動交易（要再按一次確認鍵，有時效） |
| `/auto off` | 解除武裝 |
| `/auto` | 看武裝狀態與今日額度 |
| `/why` | 跑一輪自動判斷但不下單 —— 看它現在會買什麼、為什麼不買 |
| `/scan` | 掃描 GMGN trending，評分後列出候選 |
| `/check <地址>` | 只跑檢查不下單，看閘門結果 |
| `/buy <地址> [金額]` | 準備買單，顯示確認卡（要按確認鍵，報價 2 分鐘失效） |
| `/positions` | 持倉與未實現損益 |
| `/sell <id> [百分比]` | 賣出 |
| `/stats` | 勝率、期望值、獲利因子、最大回撤（模擬與真錢分開列） |
| `/status` | 系統狀態、風控餘額 |
| `/mode` | 看目前是模擬還是真錢 |
| `/mode paper` | 切回模擬（隨時可以，不需要確認） |
| `/mode live` | 切到真錢（要按確認鍵；啟動時沒開 `GMGN_ALLOW_AUTOMATED_TRADES` 就切不了） |
| `/panic` | 全部賣光並停止交易 |
| `/resume` | 恢復交易 |
| `/restart` | 重啟機器人（重讀 `.env`）—— 只有在守門員底下跑時才會答應 |

| 上限 | 預設 | 行為 |
|---|---|---|
| 每筆投入 | $20 | 超過直接拒絕 |
| 同時持倉 | 3 個 | 滿了不給再開 |
| 在場資金 | $60 | 留 $40 當備用 |
| 單日虧損 | $20 | 觸及自動停用交易 |
| 停機線 | 淨值 $60 | 跌破全面停機 |
| 停損 | -35% | 掛成 GMGN 伺服器端 `loss_stop` |
| 停利 | +70% | 掛成 `profit_stop` |

## 熱門題材（IP）

`/hot` 做的不是「列出漲最多的幣」，而是把熱搜榜和成交榜上的**代幣名稱拆成關鍵字去分群**。

一個迷因 IP 真的熱起來時，特徵不是某一顆幣在漲，是**同一個題材一次冒出十幾顆同名近名的幣**。所以重複出現的那個關鍵字就是 IP，而顆數本身就是熱度訊號。

輸出會標出「領頭」（流動性最深的那顆）和其餘仿盤，並在這幾種情況示警：

- 同題材超過 5 顆 → 買錯合約等於全損
- 第二名流動性接近第一名 → 正主還沒分出來，這時候進場等於猜
- 最新一顆是幾十分鐘前開的 → 仿盤還在增加
- 連領頭的 rug_ratio 都偏高

**「領頭」不等於官方正主**，只是流動性最深。按檢查鍵會照樣跑完整的三道閘門。

### 關於推特

推特原文需要付費的 X API v2 或 Grok API（`SOCIAL_SEARCH_PROVIDER` + `SOCIAL_SEARCH_API_KEY`）。沒設定就不抓，而且會在輸出裡明講沒抓 —— **不會用舊知識假裝知道推特在紅什麼**。GMGN 官方 skill 也明文禁止改用爬蟲或非官方鏡像去繞。

沒接推特的代價：`/hot` 看到的是「已經有人在鏈上動作」的題材，比推特慢半步。換來的是不用付月費，而且每個數字都有出處。

## 自動交易

`AUTO_BUY=true` 只是「允許」，不是「開始」。要它真的動，還要在 Telegram `/auto on` 再按一次確認鍵。

### 為什麼武裝會過期

預設 12 小時。一個沒人看的機器人在迷因幣市場跑一個月，結局是可預期的。時效到了它會停下來並通知你，要繼續就再武裝一次。**機器人重啟也會解除武裝** —— 它在你不知情的情況下重啟並繼續花你的錢，是不能接受的。

### 自動模式比手動嚴在哪

| 條件 | 手動 | 自動 |
|---|---|---|
| 分數門檻 | 62 | 72（且不得低於手動值，設定會擋） |
| 閘門注意事項 | 顯示給你判斷 | 超過 2 條就不買 |
| 執行降級訊號 | 顯示給你判斷 | 直接不買 |
| 蜜罐「未測」 | 標示出來讓你決定 | 一律不買 |
| 拿不到 `rug_ratio` | 標示出來 | 一律不買 |
| 報價失敗 | 顯示錯誤讓你決定 | 一律不買 |

差別的原理是一致的：**「未知」對人類是「自己判斷」，對機器人只能是「不買」。**

### 停不下來的東西不存在

| 觸發 | 結果 |
|---|---|
| 每日 4 筆 / $60 | 當天不再自動買 |
| 單日虧損 $20 | 交易全面停用，武裝一併解除 |
| 淨值跌破 $60 | 同上 |
| 持倉 3 個或在場 $60 | 不再開新倉 |
| 武裝到期 | 停止並通知 |
| 連不上 Telegram 超過 15 分鐘 | 自動解除武裝（見下） |
| `/auto off`、`/panic` | 立刻停 |

### 停止它不需要碰電腦

`/auto off`（停止開新倉）和 `/panic`（全部賣光並停用）都從手機下就行。要碰電腦的只有「完全關掉程式」和「改 `.env`」，那兩件都不是停止交易的必要條件。

### 斷線保險

有一種情況會讓你失去控制權：**電腦連得到 GMGN、卻連不到 Telegram**。它會繼續自己買，而你發不出 `/auto off`。

所以自動交易每輪會檢查「最後一次跟 Telegram 通訊是多久以前」，超過 `AUTO_DEADMAN_MINUTES`（預設 15 分鐘）就自己解除武裝。原則很簡單：**「它在花錢」和「你叫不停它」不該同時成立。**

每一筆自動買入都會即時回報它買了什麼、分數多少、深度多少、為什麼過閘，以及今日剩餘額度。你睡醒要能看懂它做了什麼。

**停損停利掛在 GMGN 伺服器端**，所以機器人關掉、主機重開、你手機沒電，出場照樣執行。這比在本機跑迴圈盯價可靠得多。

### 對帳（這是整套風控能不能運作的前提）

伺服器端的停損停利成交時，GMGN **不會通知機器人**。沒有對帳的話，一個已經出場的部位會在帳本裡永遠掛著「持倉中」：虧損不入帳 → 單日止血線和停機線永遠不會觸發 → `/stats` 是假的。也就是整套風控會在你以為它在保護你的時候完全失效。

所以監控每輪會先對帳，用兩道獨立證據判定：

1. 策略單已不在 `order strategy list --type open` 裡
2. `portfolio token-balance` 顯示這顆幣餘額歸零

**兩道都成立**才平倉入帳（成交價優先取策略單歷史，取不到就用最後報價並標示為估算）。**只有一道成立**代表可能只賣了一部分、或你自己手動賣了 —— 這時不動帳，只通知你去確認。**查不到就是未知，絕不當成已出場** —— 誤判平倉會把一個還活著的部位從帳本抹掉，之後就沒人管它了。

但要注意：GMGN 文件寫明策略單是 **best-effort** —— swap 成功但策略單建立失敗時，swap 結果照樣回傳。程式偵測到這種情況會明確告訴你「這個部位沒有自動出場」，看到這個訊息就要自己盯。

## 兩層篩選

1. **掃描層**（`market trending` + `market hot-searches`，兩個來源平行抓後去重）：便宜、可以常跑。評分 9 個因子，並用 `rug_ratio`、`is_wash_trading`、`bundler_rate`、`top_10_holder_rate`、`renounced_mint` 等欄位打紅旗。

   評分裡權重最高的一項是 **`smart_degen_count` / `renowned_count`（聰明錢與 KOL 的實際持倉）** —— 整張表裡唯一「有紀錄的人拿真錢投票」的訊號，比名字熱度或動能可靠。但它只加分、不放行：KOL 也會出貨給你，所以紅旗照樣一票否決。
2. **閘門層**（`token info` + `token security`）：對候選平行驗證（預設一輪 8 顆、併發 4），沒過的記進 15 分鐘冷卻不重驗。報價（`order quote`）留到真的要買的那一顆才打 —— 它權重是 2，放在驗證階段等於每顆被刷掉的都白付一次往返。實作 GMGN 官方 skills 裡 `thresholds.md` 的量 / 深度 / 安全三道硬閘，加上方向判定（5 分鐘回撤 ≥10% 硬停，5–10% 只降級不否決）。

紅旗是**禁止進場**，不是扣分。

## 幾個會讓人賠錢的實作細節

這些都寫在程式碼註解裡，改動前先看懂：

- **Solana 的 `*_prio_fee` 三檔恆為 `1`**，那是佔位值。照它算優先費會變成 **1 SOL**。真實值在 `*_prio_fee_mixed`。
- **`liquidity` 是池子兩側之和**，約等於單邊可交易深度的兩倍。深度門檻是單邊口徑，不能直接套。
- **池子某一側的折美元儲備可能是 `"0"` 而池子完全正常**（上游沒給那一側定價）。兩側都 > 0 才取較小值，否則退回 `liquidity / 2`。
- **`token info` 回的不一定是最深的池**，深度只是下限。因此「24h 成交額遠大於池深度」是「還有別的池」的正常訊號，不是刷量。
- **稅率空字串代表未測，不是 0。**
- **開發者持倉要讀 `stat.creator_hold_rate`**，不是 `dev.top_10_holder_rate`（後者是「Top10 裡開發者相關地址佔比」，混用會誤判）。
- **代幣名稱是鏈上任何人都能填的欄位。** 所有 CLI 呼叫都用 `execFile` + 參數陣列，絕不拼 shell 字串；顯示前也會清掉控制字元。
- **限流後絕不自動重試** —— 每重試一次封禁延長 5 秒。
- **Windows 上 `gmgn-cli` 是 `.cmd` 包裝檔。** Node 18.20.2 之後不准直接 spawn `.cmd`（CVE-2024-27980 的修正），會拿到看不出原因的 `spawn EINVAL`。解法不是開 `shell: true`（那會把 `--condition-orders` 的 JSON 拆爛，而且代幣名稱是鏈上任意欄位，走 shell 等於開注入面），而是找出 `.cmd` 背後的 JS 進入點，用 node 直接跑、參數仍是陣列。見 `src/resolve-cli.js`。

## 統計為什麼把模擬和真錢分開

`/stats` 一定會分兩塊列，因為混在一起算會騙人：上真錢之後，前面那串漂亮的模擬紀錄會一直稀釋真實績效。實測情境 —— 模擬 3 勝 1 敗、真錢 2 連虧，混合統計顯示**正期望值**，真錢單獨看是**負的**。等你從混合數字發現不對，已經虧掉一輪了。

「上真錢門檻」只看模擬單。拿真錢的成績去決定要不要上真錢，邏輯是反的。

## 24 小時跑：電腦關機怎麼辦

機器人是跑在電腦上的程式，電腦關了它就停。要 24 小時跑就得找個地方掛著 —— 但這裡有個**大多數教學不會告訴你的限制**：

**GMGN 走 Cloudflare，機房／VPS／雲主機的 IP 常被直接 403。** 租一台 $5 的 VPS 掛著，是最直覺但很可能一開機就卡死的答案。付錢之前先在上面跑 `node doctor.mjs` 驗。

能 24 小時跑又保住住宅 IP 的選項：

| 方案 | 成本 | 說明 |
|---|---|---|
| **Android 手機（Termux）** | 免費 | 電信／家用網路，住宅 IP。手機本來就開著。見下 |
| 舊筆電 / 樹莓派放家裡 | 一次性 | 住宅 IP，耗電低，最穩 |
| 電腦不關機 | 免費 | 記得把睡眠關掉，睡眠會凍結程式 |
| VPS | 月費 | **可能被 403**，付錢前先驗 |
| iPhone | — | 做不到，iOS 不能跑背景常駐程式 |

### Android 手機架設

**Solana Mobile（Saga / Seeker）也是 Android**，跟一般 Android 手機一樣裝，沒有額外步驟。它的 Seed Vault 是給錢包 App 用的，跟這支機器人無關 —— `gmgn-cli` 的簽名金鑰另外存在 `~/.config/gmgn/.env`。

裝 [Termux](https://f-droid.org/packages/com.termux/)（要 F-Droid 版，Play 商店那版太舊），然後：

```bash
pkg install -y git && git clone -b claude/meme-money-program-4sb7gn https://github.com/yehiowp/Jizan.git && bash Jizan/bot/scripts/termux-setup.sh
```

腳本會裝好 Node、`gmgn-cli`、相依套件，開啟 wake lock，並寫好開機自動啟動。

**四件事沒做它就會在你沒注意的時候停掉**（腳本跑完也會再提醒一次，`node doctor.mjs` 在手機上也會逐項檢查）：

1. 裝 **Termux:API** —— 分兩半：`pkg install -y termux-api` 裝指令稿，F-Droid 上的 **Termux:API App** 才是真正去跟 Android 要 wake lock 的那個。只裝一半的話，指令不會報錯，它會一直卡在那裡等
2. 裝 **Termux:Boot** 並開啟一次 —— 沒有它，手機重開機後不會自己起來
3. 系統設定 → 電池 → Termux → **不受限制 / 不最佳化**
4. 系統設定 → WiFi → 進階 → **螢幕關閉時保持 WiFi 連線**

#### 螢幕會自動關閉，有關係嗎？

沒有。螢幕跟 CPU 是兩回事，關螢幕不會停掉程式。會停掉它的是 Android 的省電凍結，上面第 1、3、4 點就是在擋這件事。wake lock 拿到之後，螢幕黑著它照樣掃描、照樣下單。

要注意的是它**不會崩潰**：被凍結的程式是安靜地什麼都不做，從外面看跟「今天沒有符合條件的幣」一模一樣。所以手機掛機時 `HEARTBEAT_HOURS` 一定要開著（例如 12）—— 心跳沒來，是你唯一會察覺的訊號。

`scripts/run-forever.sh` 每 30 分鐘會重抓一次 wake lock，因為那個鎖會中途消失（通知列上的鎖被手動點掉、或 Termux 被系統回收後重生）。

⚠️ 所有 Termux 相關的 App 必須跟 Termux 本身同一個來源。Play 商店版跟 F-Droid 版簽章不同，混著裝的話附加元件裝得起來但完全沒作用 —— 又是一個不報錯的失敗。

⚠️ 手機上會放著 GMGN 的 API Key 和簽名私鑰。手機掉了等於鑰匙掉了 —— 設好螢幕鎖，只放賠得起的金額。

### 放在電腦上 24 小時跑（Windows）

不用裝任何東西，但要先擋掉「電腦自己睡著」—— 那是 Windows 上跟 Android 凍結一模一樣的死法：不崩潰、不留訊息，就是安靜地停擺。

用**系統管理員**的 PowerShell：

```powershell
powercfg /change standby-timeout-ac 0
powercfg /change hibernate-timeout-ac 0
```

筆電闔上螢幕還是會睡，要另外改：設定 → 系統 → 電源 → **闔上蓋子時 → 不進行動作**。

`node doctor.mjs` 在 Windows 上會直接讀 `powercfg` 驗證這兩項，沒設好會標紅。

然後用守門員啟動，程式當掉會自動重啟、紀錄檔超過 5MB 會輪替：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\run-forever.ps1
```

紀錄檔在 `%USERPROFILE%\gmgn-bot.log`。要停就在那個視窗按 Ctrl+C。

⚠️ **同一個錢包同時只能有一個機器人在跑。** 帳本存在各自的 `data/state.json`，兩個行程互相看不見 —— 部位數上限、在場資金上限、單日虧損上限、停機線會各算各的，實際風險變成兩倍。而且 GMGN 的流量額度是綁 API Key 的，兩邊共用一把 Key 會一起被 429 封。

### 關掉視窗也要跑（Windows 排程工作）

```powershell
cd $HOME\Jizan\bot
powershell -ExecutionPolicy Bypass -File scripts\install-task.ps1
Start-ScheduledTask -TaskName GMGN-Meme-Bot
```

登入時自動啟動，沒有視窗。常用指令：

| 做什麼 | 指令 |
|---|---|
| 看狀態 | `Get-ScheduledTask -TaskName GMGN-Meme-Bot \| Get-ScheduledTaskInfo` |
| 停掉 | `Stop-ScheduledTask -TaskName GMGN-Meme-Bot` |
| 移除 | `powershell -ExecutionPolicy Bypass -File scripts\install-task.ps1 -Remove` |
| 看紀錄 | `Get-Content $HOME\gmgn-bot.log -Tail 40 -Wait` |

兩個刻意的限制：

**只在你登入時啟動，不是系統開機就跑。** 你沒登入的時候它不該在交易。

**排程工作跑起來一定是模擬模式。** 真錢需要 `GMGN_ALLOW_AUTOMATED_TRADES=1`，而排程工作拿不到你 shell 裡的環境變數——那道防線本來就該由你本人每次手動開。要跑真錢就用終端機啟動，視窗留著最小化。

⚠️ 看不見的程式在花你的錢。`HEARTBEAT_HOURS` 一定要開著，心跳沒來是你唯一會察覺它停掉的訊號。

### 從 Telegram 重啟

`/restart` 會重讀 `.env` 並重新載入程式碼，不用碰電腦。

做法是「結束自己，讓守門員把自己拉回來」（離開碼 42，守門員看到會立刻重啟）。所以**沒有守門員在看的時候它會拒絕**——直接 `npm start` 跑的話，結束就等於再也起不來，而你人正好不在電腦前。那時候它會告訴你改用哪個指令啟動。

持倉不受影響（停損停利在 GMGN 伺服器端），但自動交易的武裝會解除，起來之後要重新 `/auto on`。

### 無人看管的三道保險

手機放家裡沒人看的話，這三件事決定它是「在跑」還是「你以為它在跑」：

**當機自動重啟** —— 開機腳本跑的是 `scripts/run-forever.sh`，不是直接跑 `node`。程式異常結束就等 10 秒重啟；正常關閉（Ctrl+C）則不會被拉起來。已開的倉在停機期間仍有 GMGN 伺服器端的停損保護，但機器人本身停了就不會再對帳、不會再掃描、也不會通知你。

**紀錄檔輪替** —— 超過 5MB 自動輪替，只留一份舊的。不做的話手機空間會被慢慢吃光。

**心跳** —— 預設每 12 小時回報一次持倉、損益、武裝狀態。這件事看起來多餘，直到你意識到：**「沒收到訊息」有兩種可能 —— 市場很安靜，或者它三天前就掛了。** 這兩件事對你的意義完全相反，不該長得一樣。心跳只在真的還活著時才送得出去，所以**收不到心跳本身就是訊號**。

關掉心跳：`.env` 設 `HEARTBEAT_HOURS=0`。

⚠️ **不要讓電腦和手機同時跑同一把設定。** 兩個實例各自掃描、各自下單，而風控上限是各算各的 —— 你的每日上限會變成兩倍。搬到手機就把電腦那邊 Ctrl+C 關掉。

## 限流：程式自己管好，不要去撞

GMGN 的限流是漏桶（rate=20、capacity=20），**每個指令權重不同**：`swap` 是 5、`order quote` 是 2、讀取類是 1。撞上去就是整個 IP 被封，而且文件寫明**冷卻期間每重試一次就延長 5 秒，最多 5 分鐘**。

所以每個請求送出前都會先過客戶端漏桶：額度不夠就等到補回來再送，而不是送出去被拒。真的被封了（429）就記下 `reset_at`，**解封前所有請求在本地就被擋下，一個都不送** —— 真正讓封禁一直延長的，是冷卻期間還在敲門。

多鏈掃描會顯著增加請求量（3 條鏈 × 2 個來源 = 每輪 6 個，加上驗證 8 顆 × 2 = 16 個），這個節流不是可選的。

**至於 Cloudflare 的 403：那不是能「解決」的東西。** 它看的是 IP 信譽。正解是用住宅 IP，不是去繞過它 —— 官方 skill 也明文禁止改用爬蟲或非官方鏡像。
