# GMGN 迷因幣 Telegram 機器人

用 GMGN 官方 `gmgn-cli` 執行交易的 Telegram 機器人：掃描候選幣、跑完整安全檢查、你在 Telegram 按確認後才下單，並且在買入的同時把停損停利掛到 GMGN 伺服器端。

兩種模式：

- **手動**（預設）：機器人找到候選就通知你，你按確認鍵才下單。
- **自動**：武裝之後它自己選、自己買，不再問你。門檻比手動嚴，武裝會自己到期。

## 先講清楚

- **不保證獲利。** 迷因幣絕大多數歸零。這支程式能做的是過濾掉明顯的陷阱、強制固定部位大小、確保每一單都有停損。它不預測價格。
- **自動模式會更快賠光。** 它照單全收每個符合條件的訊號，沒有「這個我看不順眼」這種判斷。所以自動模式的門檻設得比手動高，而且有每日筆數與金額上限。
- **不碰你的私鑰。** 私鑰由 `gmgn-cli` 自己管在 `~/.config/gmgn/.env`，這支程式不讀、不存、不傳。
- **摩擦成本是真的。** 每次進出都要付 GMGN 抽成 + 優先費 + 小費 + 滑價。用 $20 的部位去對抗這個摩擦，勝率門檻比你想的高很多。

## 需要準備

| 項目 | 怎麼拿 |
|---|---|
| Node.js 20+ | |
| `gmgn-cli` | `npm install -g gmgn-cli` |
| GMGN API Key | `gmgn-cli config` 會告訴你去哪申請，拿到後 `gmgn-cli config --apply <KEY>` |
| 錢包私鑰 | 由 `gmgn-cli config` 一起設定。**用小額燒錢包，不要用主錢包。** |
| Telegram Bot Token | 跟 [@BotFather](https://t.me/BotFather) 說 `/newbot` |

⚠️ `gmgn-cli` **只走 IPv4**。主機開著 IPv6 會拿到 401/403，而且錯誤訊息看不出真正原因。

## 安裝

```bash
cd bot

# 編輯 .env：填 TELEGRAM_TOKEN、OWNER_ID、GMGN_WALLET_ADDRESS
```

## 上線順序（不要跳步）

### 第一步：自檢（不花錢）

```bash
npm run selftest
```

會逐項檢查 API Key、IPv6、gas 報價、trending 資料源、安全檢查端點、報價、Telegram 連線。**有任何 ❌ 就先修，不要往下走。**

### 第二步：模擬跑一週（`DRY_RUN=true`）

```bash
npm start
```

在 Telegram 用 `/scan` 找候選、`/buy <地址>` 走完整流程。它會照真實報價記帳，但不送鏈上交易。

**想直接看自動模式**：`.env` 設 `AUTO_BUY=true`，重啟，`/auto on`。模擬模式下它會自己選、自己記帳，但不會花錢。這是觀察它選幣品質最省錢的方式 —— 跑幾天看 `/stats`。

一週後看 `/stats`：

- **期望值是負的** → 這套打法在現在的行情下不賺錢。改參數或收手，不要拿真錢去試。
- **期望值是正的但只有 5 筆** → 樣本太少，那是運氣。繼續跑。

### 第三步：真錢（確定要再做）

```bash
# 在 .env 把 DRY_RUN 改成 false，然後：
export GMGN_ALLOW_AUTOMATED_TRADES=1
npm start
```

`GMGN_ALLOW_AUTOMATED_TRADES=1` **必須由你自己在 shell 設定**。這是 GMGN 的程式碼層防線：CLI 平常會從 `/dev/tty` 讀一個手打的 `yes`，`--yes` 這個旗標單獨用會被拒絕，就是為了擋掉「AI 讀到惡意指令就自己加 `--yes`」。官方文件把這個環境變數留給「刻意的無人值守自動化」，而設定它的人必須是操作者本人。

這支程式不會、也不該替你設定它。沒設定的話，真錢模式會直接拒絕啟動並告訴你原因。

要跑真錢自動交易，三道開關要同時成立，缺一不可：

1. `.env` 裡 `DRY_RUN=false`
2. 你的 shell 裡 `GMGN_ALLOW_AUTOMATED_TRADES=1`
3. `.env` 裡 `AUTO_BUY=true`，**而且**在 Telegram `/auto on` 按下確認

第 3 項有時效，另外兩項沒有。

## 熱門題材（IP）

`/hot` 做的不是「列出漲最多的幣」，而是把熱搜榜和成交榜上的**代幣名稱拆成關鍵字去分群**。

一個迷因 IP 真的熱起來時，特徵不是某一顆幣在漲，是**同一個題材一次冒出十幾顆同名近名的幣**。所以重複出現的那個關鍵字就是 IP，而顆數本身就是熱度訊號。

輸出會標出「領頭」（流動性最深的那顆）和其餘仿盤，並在這幾種情況示警：

- 同題材超過 5 顆 → 買錯合約等於全損
- 第二名流動性接近第一名 → 正主還沒分出來，這時候進場等於猜
- 最新一顆是幾十分鐘前開的 → 仿盤還在增加
- 連領頭的 rug_ratio 都偏高

**「領頭」不等於官方正主**，只是流動性最深。按檢查鍵會照樣跑完整的三道閘門。

### 關於推特

推特原文需要付費的 X API v2 或 Grok API（`SOCIAL_SEARCH_PROVIDER` + `SOCIAL_SEARCH_API_KEY`）。沒設定就不抓，而且會在輸出裡明講沒抓 —— **不會用舊知識假裝知道推特在紅什麼**。GMGN 官方 skill 也明文禁止改用爬蟲或非官方鏡像去繞。

沒接推特的代價：`/hot` 看到的是「已經有人在鏈上動作」的題材，比推特慢半步。換來的是不用付月費，而且每個數字都有出處。

## 自動交易

`AUTO_BUY=true` 只是「允許」，不是「開始」。要它真的動，還要在 Telegram `/auto on` 再按一次確認鍵。

### 為什麼武裝會過期

預設 12 小時。一個沒人看的機器人在迷因幣市場跑一個月，結局是可預期的。時效到了它會停下來並通知你，要繼續就再武裝一次。**機器人重啟也會解除武裝** —— 它在你不知情的情況下重啟並繼續花你的錢，是不能接受的。

### 自動模式比手動嚴在哪

| 條件 | 手動 | 自動 |
|---|---|---|
| 分數門檻 | 62 | 72（且不得低於手動值，設定會擋） |
| 閘門注意事項 | 顯示給你判斷 | 超過 2 條就不買 |
| 執行降級訊號 | 顯示給你判斷 | 直接不買 |
| 蜜罐「未測」 | 標示出來讓你決定 | 一律不買 |
| 拿不到 `rug_ratio` | 標示出來 | 一律不買 |
| 報價失敗 | 顯示錯誤讓你決定 | 一律不買 |

差別的原理是一致的：**「未知」對人類是「自己判斷」，對機器人只能是「不買」。**

### 停不下來的東西不存在

| 觸發 | 結果 |
|---|---|
| 每日 4 筆 / $60 | 當天不再自動買 |
| 單日虧損 $20 | 交易全面停用，武裝一併解除 |
| 淨值跌破 $60 | 同上 |
| 持倉 3 個或在場 $60 | 不再開新倉 |
| 武裝到期 | 停止並通知 |
| `/auto off`、`/panic` | 立刻停 |

每一筆自動買入都會即時回報它買了什麼、分數多少、深度多少、為什麼過閘，以及今日剩餘額度。你睡醒要能看懂它做了什麼。

**停損停利掛在 GMGN 伺服器端**，所以機器人關掉、主機重開、你手機沒電，出場照樣執行。這比在本機跑迴圈盯價可靠得多。

但要注意：GMGN 文件寫明策略單是 **best-effort** —— swap 成功但策略單建立失敗時，swap 結果照樣回傳。程式偵測到這種情況會明確告訴你「這個部位沒有自動出場」，看到這個訊息就要自己盯。

## 兩層篩選

1. **掃描層**（`market trending`）：便宜、可以常跑。評分 9 個因子，並用 `rug_ratio`、`is_wash_trading`、`bundler_rate`、`top_10_holder_rate`、`renounced_mint` 等欄位打紅旗。

   評分裡權重最高的一項是 **`smart_degen_count` / `renowned_count`（聰明錢與 KOL 的實際持倉）** —— 整張表裡唯一「有紀錄的人拿真錢投票」的訊號，比名字熱度或動能可靠。但它只加分、不放行：KOL 也會出貨給你，所以紅旗照樣一票否決。
2. **閘門層**（`token info` + `token security`）：只對你真的要買的那一顆跑。實作 GMGN 官方 skills 裡 `thresholds.md` 的量 / 深度 / 安全三道硬閘，加上方向判定（5 分鐘回撤 ≥10% 硬停，5–10% 只降級不否決）。

紅旗是**禁止進場**，不是扣分。

## 幾個會讓人賠錢的實作細節

這些都寫在程式碼註解裡，改動前先看懂：

- **Solana 的 `*_prio_fee` 三檔恆為 `1`**，那是佔位值。照它算優先費會變成 **1 SOL**。真實值在 `*_prio_fee_mixed`。
- **`liquidity` 是池子兩側之和**，約等於單邊可交易深度的兩倍。深度門檻是單邊口徑，不能直接套。
- **池子某一側的折美元儲備可能是 `"0"` 而池子完全正常**（上游沒給那一側定價）。兩側都 > 0 才取較小值，否則退回 `liquidity / 2`。
- **`token info` 回的不一定是最深的池**，深度只是下限。因此「24h 成交額遠大於池深度」是「還有別的池」的正常訊號，不是刷量。
- **稅率空字串代表未測，不是 0。**
- **開發者持倉要讀 `stat.creator_hold_rate`**，不是 `dev.top_10_holder_rate`（後者是「Top10 裡開發者相關地址佔比」，混用會誤判）。
- **代幣名稱是鏈上任何人都能填的欄位。** 所有 CLI 呼叫都用 `execFile` + 參數陣列，絕不拼 shell 字串；顯示前也會清掉控制字元。
- **限流後絕不自動重試** —— 每重試一次封禁延長 5 秒。

## 測試

```bash
npm test
```

141 條斷言，把 `gmgn-cli` 換成假的跑完整條買賣流程。不需要 API Key、不連網、不會送出任何交易。涵蓋：評分邊界、12 種陷阱是否被攔、蜜罐四層判定、深度三種取法、5 分鐘回撤硬停與降級、CLI 參數組裝（含惡意字串不被拆開）、限流/401/自動下單開關的錯誤處理、訂單輪詢必須到 `confirmed`、風控七道上限、自動停機、壞檔復原。

自動交易另有 14 條，全部是驗證「它在什麼情況下**不會**買」：未武裝、武裝過期、每日筆數與金額上限、分數未達自動門檻、蜜罐未測、執行降級、報價失敗、注意事項過多、持倉已滿、交易被停用時連武裝一起解除、一輪最多一筆、設定值不合理會被擋。
